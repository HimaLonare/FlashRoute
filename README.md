# FlashRoute: AI-Powered Delivery ETA & Route Optimization

An end-to-end logistics optimization system that predicts food-delivery
ETAs with machine learning and computes optimized delivery routes with
classical graph algorithms (Dijkstra & A*), served through a Flask web
application.

## Problem statement

Food delivery platforms need two things at order time: **"how long will
this take?"** and **"what's the fastest way there?"**. FlashRoute
answers both — an ML regression model predicts ETA from order/driver/
distance features, while a graph-search layer computes an optimized
route over a real street network and renders it on an interactive map.

## Dataset

Real-world food delivery data (~45,600 rows): driver age/rating,
restaurant & delivery GPS coordinates, order type, vehicle type, and
the target, `Time_taken(min)`. **No synthetic data was used anywhere
in this project.**

### Known data quality issues (found and fixed during EDA)
- Trailing whitespace in categorical columns (`'Snack '` vs `'Snack'`).
- 431 rows with sign-flipped (negative) latitude/longitude — impossible
  for India, fixed with `abs()`.
- 53 rows with `Delivery_person_Ratings = 6.0` on a 1–5 scale — clipped.
- 3,640 rows with placeholder `(0, 0)` restaurant coordinates ("null
  island") — kept for ETA regression (their relative distance is still
  realistic) but excluded from real-map route optimization.

### Honest model-ceiling note
This dataset has **no traffic, weather, or time-of-day features** — the
biggest real-world ETA drivers. Correlations between available features
and `Time_taken(min)` top out around 0.3, so trained models land around
**R² ≈ 0.4**. This is a legitimate result given the data available, not
a bug — documented here rather than oversold.

## How to run

```bash
pip install -r requirements.txt

# 1. Clean the raw data
python src/data_cleaning.py

# 2. Engineer features
python src/feature_engineering.py

# 3. Train and compare models (saves the best one by RMSE)
python src/model_training.py

# 4. Generate realistic restaurant/delivery dropdown options
python src/generate_location_options.py

# 5. Run the app
python app.py
```

Then open `http://localhost:5000`.

## Model results

| Model | MAE (min) | RMSE (min) | R² |
|---|---|---|---|
| Linear Regression | 6.20 | 7.75 | 0.316 |
| Random Forest | 5.70 | 7.25 | 0.400 |
| XGBoost | *run `model_training.py` to populate* | | |

Random Forest outperforms Linear Regression, indicating the true
relationship between distance/age/rating and delivery time is
non-linear (e.g. distance likely interacts with vehicle type).

## Route optimization: Dijkstra vs A*

Both algorithms are guaranteed to find the same shortest path when the
A* heuristic is admissible (never overestimates remaining distance) —
verified here using Haversine distance as the heuristic.

**A* is not universally faster.** On a small/uniform test graph (400
nodes), A*'s per-node heuristic computation cost outweighed its search-
space pruning, making it marginally *slower* in wall-clock time than
Dijkstra, despite exploring ~5% fewer nodes. On large, irregular real
street networks, A*'s goal-directed pruning is expected to dominate and
produce a clear speedup — this is exactly why production routing
engines (e.g. OSRM) use A*-family algorithms rather than plain
Dijkstra. Run `src/demo_route_optimization.py` to reproduce.

## Known limitations & future improvements
- Dataset lacks traffic/weather/time features — the largest lever for
  improving ETA accuracy would be adding these.
- Restaurant/delivery location names are placeholders over real
  coordinates (the dataset has no business names) — a production
  version would integrate a geocoding/restaurant-directory API.
- `build_feature_row()` in `app.py` re-implements bucket-encoding logic
  from `feature_engineering.py` for single-row inference; a future
  refactor could share one function for both training and serving to
  eliminate any risk of drift between them.
- No authentication, rate limiting, or production WSGI server (e.g.
  gunicorn) configured — `app.run(debug=True)` is for local development
  only.
